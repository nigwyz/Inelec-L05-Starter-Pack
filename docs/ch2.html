1Architecture vs. organization

Computer Architecture

Attributes visible to the programmer that directly affect the logical execution of a program.

  • Instruction set
  • Number of bits (word size, register size)
  • Memory addressing modes
  • Data types and registers visible to code

The contract: “if you write this instruction, this is what it means.”

Computer Organization

The operational units and their interconnections that realize the architectural specification.

  • ALU design and width
  • Control unit implementation
  • Bus structure and timing
  • Cache size and organization

The implementation: “this is how the hardware actually does it.”

A computer is a hierarchical system. At every level, structure is how components relate, and function is what each component does as part of that structure.

Computer structure : CPU, memory, bus, I/O
CPU structure      : ALU, registers, control unit, internal bus
Control unit       : sequencing logic, registers, decoders, memory control

2A short evolution

YearMachine / eventWhy it matters
1947ENIACFirst electronic computer: 30 tons, 18 000 vacuum tubes, decimal, programmed manually by switches and cables.
1947Transistor (Bell Labs)Replaced vacuum tubes; smaller, cooler, more reliable computers.
1952IAS / Von Neumann machineStored-program concept: instructions live in the same memory as data. Prototype of today’s general-purpose computer.
1965Moore’s lawTransistor count and frequency roughly double every 18 months (originally stated as 18–24 months).
1971Intel 4004First microprocessor: a 4-bit CPU on one chip, 2300 transistors, 108 kHz.
1972Intel 8008First 8-bit microprocessor; first commercially available processor.
The key idea. Before stored programs, changing a computation meant rewiring the machine. After it, changing the computation means loading different bytes into the same memory. That is why a general-purpose computer can run a text editor, a compiler, and a game without changing its hardware.

3Von Neumann and Harvard

Von Neumann architecture rests on three ideas:

  1. One memory stores both data and instructions, and it is read/write.
  2. Memory contents are addressable by location—a pointer is just an address.
  3. Execution is sequential from one instruction to the next unless an instruction explicitly changes the flow.

At the top level, a computer has four elements: the CPU, memory, I/O peripherals, and the communication buses that connect them.

Harvard architecture uses two separate memories—one for program, one for data—often with separate buses. It appears in DSPs and in some embedded and image-processing systems. Its advantage is that an instruction fetch and a data access can happen at the same time; its cost is more pins, more memory, and a less flexible memory map.

4The CPU

The CPU performs one basic job: execute instructions. Each instruction has two parts:

  • Opcode—what operation to perform (ADD, LOAD, STORE, JUMP…).
  • Operand—references to the inputs and outputs: a register, a memory address, or an immediate value.

The basic operation classes are arithmetic/logic, data movement, and control flow (conditional jump, branch, call).

Four CPU blocks

Registers

Fast temporary storage of data, addresses, and instructions.

ALU

Performs the arithmetic and logical operation.

Control Unit

Fetches, decodes, and asserts the control signals.

Internal bus

Moves values between the blocks.

5Memory: words, bytes, endianness, stack

RAM is conceptually a table of N locations. Each location has a unique address and stores a fixed number of bits (the word length). The number of locations is the depth; the bits per location is the width; and:

capacity = depth × width

The notation [X] means “the content of the memory location whose address is X”. So [1234H] = 56H means address 1234H holds 56H.

ROM can only be read; RAM (read/write memory) can be read and written. The CPU normally accesses one location at a time.

Word-addressable vs. byte-addressable

In word-addressable memory, each address points to a whole word; that is inefficient for characters and strings. In byte-addressable memory, each address points to one byte, and a 16- or 32-bit value spans two or four consecutive locations. Most modern CPUs are byte-addressable.

Little-endian vs. big-endian

For a multi-byte value, the bytes must be ordered. Little-endian stores the least-significant byte at the lowest address; big-endian stores the most-significant byte first.

For the 32-bit value 12345678H stored at address 10H:

AddressLittle-endianBig-endian
10H7812
11H5634
12H3456
13H1278

x86 is little-endian; Motorola 68k and SPARC are big-endian. The Z80 and the course’s hypothetical CPUs are little-endian.

Stack memory

A stack is read/write memory with last-in, first-out access. The SP holds the address of the last saved item. PUSH saves a value and POP retrieves it; SP updates automatically.

Memory map

With N address lines, the CPU can address 2N locations. The address range is divided into regions with different roles—monitor ROM, program/data RAM, user range, I/O ports. That division is the memory map.

The course example (MDA-WINZ80):

RangeRoleSize
0000–1FFFHMonitor EEPROM8 KB
2000–3FFFHProgram and data memory8 KB
4000–FFFFHUser range48 KB

Size of a range [A, B] is B − A + 1 locations. For 16-bit addresses the whole space is 64 KB; a byte-addressable 64 KB memory therefore holds 64 K bytes = 512 Kbit.

6I/O peripherals

Input modules move data from the outside world into the CPU; output modules move data out. From the CPU’s internal point of view, an I/O device behaves much like a memory location: each device has a unique port/address that can be read or written.

That similarity is deliberate. It allows the same load/store machinery—and, in many CPUs, the same instructions—to reach both memory and peripherals. Chapter 7 of the course will separate memory-mapped I/O from isolated I/O; for now, remember that “I/O is an address the CPU can read or write.”

7System buses

A bus is a shared communication path. All peripherals connect to it, but only one device may drive it at a time; the others must be in the high-impedance state. That is why devices connect through tri-state buffers.

BusDirectionCarriesWidth determines
Data busBidirectionalData between CPU, memory, I/OHow many bits move at once
Address busUnidirectional (out of CPU)The address being accessedMaximum addressable memory: 2N
Control busMixedRead/write, clock, interrupt, reset…What operation and when

A 16-bit address bus addresses 216 = 65 536 = 64 K locations. If each location is one byte, that is 64 KB; if the memory is word-addressable with a 16-bit word, the capacity is 64 K words = 128 KB.

Book corner — bus timing and arbitration (Stallings §3.4). A bus transfer needs more than data lines: it needs a timing rule. In synchronous timing, every event is tied to a clock and both sides must meet the same clock budget. In asynchronous timing, a handshake (request/acknowledge) lets a slow device take as long as it needs. When several devices want the bus, an arbiter grants it—centrally (one controller) or distributively (daisy-chain or independent requests). The exam’s “only one device drives the bus” rule is the reason arbitration exists at all.

8Instructions and assembly language

An assembly program is a sequence of machine instructions. Every instruction encodes two kinds of information:

  • Opcode field—the operation.
  • Operand fields—immediate value, memory address (pointer), or register.

Instructions may have zero, one, two, or three operands. More operands make assembly easier to read but make each instruction longer.

Reading an assembly line

start:  addi  $t0, $t0, 1    ; increment i

start   optional label = address of this instruction
addi    opcode
$t0     destination register
$t0     source register
1       immediate source operand
; ...   comment

Machine code is the binary or hex representation of that instruction. For example, the MIPS instruction add $t0, $t1, $t2 becomes:

0000 0001 0010 1011 1000 0000 0100 0000₂
= 012B8040H

9Fetch, decode, execute

Program execution repeats two phases:

  1. Fetch: read the instruction at [PC] into IR.
  2. Decode/execute: decode it, read operands, perform the operation, store the result.

The fetch cycle, precisely

MAR ← PC
MBR ← [MAR]        (memory read)
IR  ← MBR
PC  ← PC + instruction_size

So at the end of a fetch, MAR holds the address of the last byte fetched, MBR holds the last byte read, and IR holds the complete instruction. The PC has already moved to the next instruction.

How many memory reads? One read per bus-width chunk. In the course’s hypothetical machine, instructions are 16 bits and the data bus is 16 bits, so one read fetches an instruction. If the data bus were 8 bits, the same instruction would need two reads. This exact distinction appears in Quiz #1.

Worked example: the 16-bit hypothetical machine

Specifications (slides 50–57): instructions are 16 bits, the address bus is 12 bits, the format is 4-bit opcode + 12-bit address, and there is a single accumulator AC. Opcodes: 1H load AC from memory, 2H store AC, 5H add memory to AC, 7H halt.

AddressContentMeaning
300H1940HLoad AC from 940H
301H5941HAdd [941H] to AC
302H2941HStore AC to 941H
303H7940HHalt
940H0003HData
941H0002HData
942H0001HData

Step 1 — fetch the first instruction. PC = 300H, so MAR = 300H, MBR = [300H] = 1940H, IR = 1940H, PC = 301H.

Step 2 — execute it. Opcode 1H = load; address = 940H. AC ← [940H] = 0003H.

Step 3 — fetch the second. MAR = 301H, MBR = 5941H, IR = 5941H, PC = 302H.

Step 4 — execute. Opcode 5H = add; address = 941H. AC ← 0003H + [941H] = 0003H + 0002H = 0005H.

Step 5 — fetch the third. MAR = 302H, MBR = 2941H, IR = 2941H, PC = 303H.

Step 6 — execute. Opcode 2H = store; address = 941H. [941H] ← 0005H.

Step 7 — fetch the fourth. MAR = 303H, MBR = 7940H, IR = 7940H, PC = 304H.

Step 8 — execute. Opcode 7H = halt. Execution stops.

10Performance: MIPS and MFLOPS

Performance is not one number. The course lists speed, cost, size, reliability, and power consumption. For instruction throughput, the key relation is:

CPI_avg = Σ (fraction_i × CPI_i)
MIPS    = clock_frequency / (CPI_avg × 10^6)

MFLOPS = number_of_floating_point_operations
         ────────────────────────────────────────
                execution_time × 10^6

For the 2021–22 control: 200 instructions total; 100 take 4 cycles, 60 take 7, 40 take 10; clock = 2 GHz.

fractions: 100/200 = 0.5, 60/200 = 0.3, 40/200 = 0.2
CPI = 0.5×4 + 0.3×7 + 0.2×10 = 2.0 + 2.1 + 2.0 = 6.1

MIPS = 2×10^9 / (6.1×10^6) ≈ 328 MIPS
Interactive · MIPS calculatoredit the instruction mix
Careful with units. GHz = 109 Hz. The “106” in the MIPS formula converts cycles per second to millions of instructions per second. A result of 328 means 328 million instructions per second.
