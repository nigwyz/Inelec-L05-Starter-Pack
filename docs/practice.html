Past-Control Practice

Six recurring skills explain almost every control question. Each section below teaches the method, works an example, and then gives you a fresh problem with the solution hidden.

How to use this page. Attempt each problem on paper before opening the solution. Reading a solution feels productive; reproducing it from an empty page is the actual skill. The year references point to the style of the question, not to a promise that this year’s paper repeats it.

ANumber interpretation and flags

Method

  1. Write the operation in binary using the stated width.
  2. Unsigned: if the true result is negative, add 2n (wrap modulo 2n).
  3. 8-bit CPU: perform two’s-complement addition: A − B = A + (B̄ + 1). Keep the low n bits.
  4. Decimal signed result: if the MSB is 1, invert + 1 and add a minus sign.
  5. Carry: for addition, carry out of the MSB. For subtraction, carry = 1 means no borrow (the CPU computed A + B̄ + 1 and carried out).
  6. Overflow: only if the two operands have the same sign and the result has the opposite sign. Equivalently, carry into MSB ≠ carry out of MSB.

Worked example — the 2025–26 style

Using 8 bits, compute 53H − 35H and 35H − 53H; then give the carry and overflow flags.

53H = 0101 0011₂      35H = 0011 0101₂

53H − 35H:
  53H + (35H inverted + 1)
  = 53H + CAH + 1 = 53H + CBH
  = 1EH   (true result +30; no borrow)

35H − 53H:
  35H + (53H inverted + 1)
  = 35H + ACH + 1 = 35H + ADH
  = E2H   (8-bit pattern; true result −30)

Decimal signed: E2H → invert 1DH → +1 → 1EH = 30 → −30

Flags:
  53H − 35H: carry = 1 (no borrow), overflow = 0
  35H − 53H: carry = 0 (borrow),    overflow = 0

Why is overflow 0? For subtraction, think of it as A + (−B). In the first case the effective operands are +83 and −53; in the second they are +53 and −83. In both cases the operands have opposite signs, so the result cannot overflow, and +30 / −30 are both in range. The carry differs because the second subtraction had to borrow.

Your turn
Using 8 bits, give 7BH − B7H as (a) unsigned hex and (b) signed decimal.
Show solution
7BH = 123, B7H = 183. 123 − 183 = −60. Modulo 256: 256 − 60 = 196 = C4H. As an 8-bit two’s-complement pattern, C4H = 1100 0100: invert → 0011 1011, +1 → 0011 1100 = 60, so −60.
Your turn
Which operation sets carry but not overflow on an 8-bit CPU?
Show solution
FFH + 01H = 100H → 8-bit result 00H with carry 1. Signed: −1 + 1 = 0, no overflow. 7FH + 01H = 80H is signed +127 + 1 = +128 → overflow, but no carry. 80H + 80H = 100H → 00H with carry; signed −128 + −128 = −256 → overflow too.

BInstruction size and hex encoding

Method

  1. Find the instruction in the table. The table gives the opcode bytes and the operand type.
  2. Count: opcode bytes + operand bytes.
  3. Encode each operand: 8-bit n is one byte; 16-bit nn is two bytes, low byte first (little-endian).
  4. For register-coded instructions, substitute each register’s 3-bit code into the binary pattern.

Worked example — the Z80 set

JR Z,−5      opcode 28H + 8-bit displacement        → 2 bytes
             −5 = FBH (two's complement of 5)          → 28 FBH

LD IX,F1H    DD 21H + 16-bit nn                     → 4 bytes
             nn = 00F1H, little-endian                 → DD 21 F1 00H

LD A,(IX+5)  DD 01 RRR 110 + n
             R = A = 111 → 01 111 110 = 7EH          → DD 7E 05H (3 bytes)

The size follows the format, not the number of digits you write. LD IX,F1H is still 4 bytes because the format reserves a 16-bit operand.

Your turn
Give the size and hex code of LD A,(IX+5).
Show solution
DD is the prefix, 7E encodes LD A,(IX+n), and 05 is the signed displacement. Three bytes total: DD 7E 05H. The displacement is one byte, not two.
Your turn
Which instruction is 2 bytes long?
Show solution
JR Z,n = opcode + 8-bit displacement = 2 bytes. LD IX,(nn) is 4 bytes; LD HL,(nn) and LD (IX+n),A are 3 bytes.

CFetch/execute register traces

The only method you need

FETCH of an instruction of size S:
  MAR ← PC
  MBR ← [MAR]        (repeat for each byte, incrementing MAR)
  IR  ← the complete instruction
  PC  ← PC + S

EXECUTE:
  decode IR
  read operands (register or memory)
  perform the operation
  write the result
  leave PC, MAR, MBR at their last values unless the instruction changes them
The trap. MAR is not “the address of the instruction” after the fetch—it is the address of the last byte read. MBR is the last byte read, not the whole instruction. IR is the whole instruction. PC already points to the next instruction.

Worked example — JR FEH at 2509H

JR n is 18H + n. For JR FEH, the encoding is 18 FEH, 2 bytes, stored at 2509H and 250AH.

Before fetch: PC = 2509H

Fetch:
  MAR ← 2509H
  MBR ← [2509H] = 18H
  IR  ← 18H           (first opcode byte)
  PC  ← 250AH
  MAR ← 250AH
  MBR ← [250AH] = FEH
  IR  ← 18FEH
  PC  ← 250BH

After fetch:  PC = 250BH, MAR = 250AH, MBR = FEH

Execute:
  n = FEH = −2
  PC ← PC + n = 250BH − 2 = 2509H
  MAR and MBR are unchanged: 250AH and FEH

After execute: PC = 2509H, MAR = 250AH, MBR = FEH

This is the 2025–26 Q1.6–1.7 pattern. Notice the execute changes PC only; MAR/MBR keep their fetch values.

Your turn
LD IX,3000H is stored at 2000H. After the fetch cycle only, what are PC, MAR, MBR?
Show solution
The instruction is DD 21 00 30 (4 bytes). Fetch reads four bytes, ending at 2003H. So MAR = 2003H, MBR = 30H, and PC = 2000H + 4 = 2004H. If your course defines the fetch as only the opcode bytes, use that convention—but check the control’s own wording.

DStack and subroutine behaviour

Method

  • PUSH: SP ← SP − 2 (for a 16-bit register), then the high byte is written at [SP+1] and the low byte at [SP]. On a downward-growing stack, “top” is the lowest address.
  • POP: low byte ← [SP], high byte ← [SP+1], then SP ← SP + 2.
  • MAR after a PUSH/POP is the address of the last byte accessed: for POP, SP+1; for PUSH, SP (the low byte is written last on many CPUs).

Worked example — POP HL at SP = 3009H

Memory: [3009H] = 09H, [300AH] = FAH.

POP HL:
  L  ← [SP]   = [3009H] = 09H
  H  ← [SP+1] = [300AH] = FAH
  HL = FA09H
  SP ← SP + 2 = 300BH
  MAR = 300AH   (last byte read)
  MBR = FAH     (last byte read)

Little-endian is why the low byte (09H) is at the lower address. H = FAH, L = 09H, so HL = FA09H—not 09FAH.

Your turn
SP = 3F07H, B = B1H, C = C1H. After PUSH BC, what are SP and the two memory bytes?
Show solution
PUSH decrements SP by 2 first: 3F07H − 2 = 3F05H. The register pair BC is stored low byte first: C (low) at 3F05H, B (high) at 3F06H. So [3F05H]=C1H, [3F06H]=B1H, and the new top is 3F05H.

EInterrupts and ISR addressing

The Z80 IM2 sequence

  1. Finish the current instruction. PC now points to the next instruction.
  2. Push PC: SP ← SP − 2; [SP] ← low byte of PC, [SP+1] ← high byte.
  3. Form the vector pointer: I × 256 + device_data.
  4. Read two bytes at that pointer (little-endian) → new PC = ISR start address.
  5. Fetch the first ISR instruction from that address.

Worked example — IM2 with I = 23H, device = 4CH

Interrupt arrives during LD IX,0H at 2100H. That instruction is DD 21 00 00, 4 bytes, so after fetching it PC = 2104H. SP = F612H. Memory at 234CH contains 17H, at 234DH contains F7H.

Before the interrupt cycle:
  SP = F612H
  PC = 2104H          (LD IX,0H is 4 bytes; PC has advanced)

Interrupt cycle:
  push PC → SP = F610H, [F610H]=04H, [F611H]=21H
  pointer = 2300H + 4CH = 234CH
  ISR address = [234DH][234CH] = F717H
  PC ← F717H

After the interrupt cycle:
  SP = F610H
  PC = F717H

Before fetching the first ISR instruction:
  IR  = DD210000H     (the interrupted instruction is still in IR)
  MAR = 234DH         (last byte read to form the ISR address)
  MBR = F7H           (last byte read)

Note the two distinct memory accesses: the stack write, then the vector read. Keep them separate or the addresses will blur.

Your turn
Z80 IM1 interrupt. Where does the CPU jump?
Show solution
IM1 always uses 0038H. IM0 uses one of 00H…38H selected by hardware; IM2 uses [I×256 + data]; NMI uses 0066H; reset uses 0000H.

FProgram size, instruction count, cycles

Method

  • Disassemble from the start address until the halt (or until the bytes stop forming valid instructions).
  • Sum each instruction’s size in bytes. The total is the program size in bytes; multiply by 8 for bits.
  • Count instructions separately from bytes.
  • For cycles: list each machine cycle (opcode fetch, operand fetch, memory read/write) and multiply by its T-state count.

Worked example — the 2025–26 program at 2000H

2000H  DD 21 00 30   LD IX,3000H     4 bytes
2004H  DD 7E 00      LD A,(IX+0)     3 bytes
2007H  3C            INC A           1 byte
2008H  DD 77 00      LD (IX+0),A     3 bytes
200BH  76            HALT            1 byte

Total: 4+3+1+3+1 = 12 bytes = 96 bits
Instructions: 5

The last instruction starts at 200BH, not 200CH. Program bytes run 2000H…200BH inclusive.

Your turn
How many T-states does LD IX,nn take? (opcode fetch = 4, operand fetch = 3 per byte)
Show solution
DD 21 is a two-byte opcode: two opcode fetches = 8 T-states. The 16-bit operand is two operand fetches = 6 T-states. Total 14.
Your turn
LD HL,(nn) uses which machine cycles?
Show solution
LD HL,(nn) is 2A + nn (3 bytes). It fetches the opcode, fetches the 16-bit address as two operand bytes, then reads the two data bytes at that address: 4 + 3 + 3 + 3 + 3 = 16 T-states.

GOlder custom-CPU style

The older controls use a made-up 8-bit CPU instead of the Z80. The registers and opcodes change, but the method does not. This is the transfer skill the exam is really testing.

Worked example — 8-bit bus, 16-bit instructions

Specification: little-endian, byte-addressable memory, 16-bit address bus, 8-bit data bus, instructions 16 bits long, and a 16-bit IR. Memory at 900H begins:

900H: 0A 19 0C 59 0E 29 00 79 23 45 67 89 AB CD EF 01

1. How many memory reads to fetch one instruction? The instruction is 16 bits but the data bus moves 8 bits per read. Two reads.

2. IR, MBR, and PC after fetching the first instruction?

MAR ← 900H; MBR ← 0AH; PC ← 901H
MAR ← 901H; MBR ← 19H; PC ← 902H
Little-endian: the first byte is the low byte.
IR = 190AH
MBR = 19H      (last byte read)
PC  = 902H     (next instruction)

3. How many instructions in the program? Decode from 900H until the halt. If the program is four 16-bit instructions ending in a halt at 906H, the program is 8 bytes = 64 bits, and the last instruction starts at 906H.

4. What changes if the data bus is 16 bits? The same instruction now takes one read, but IR is unchanged. The bus width affects the number of reads, not the instruction size.

Your turn
An 8-bit CPU with a 16-bit address bus and an 8-bit data bus fetches a 16-bit instruction. How many memory reads are needed?
Show solution
The instruction is 16 bits; each read returns 8 bits. Two reads. This is independent of the opcode—it follows from the bus width and instruction size.
Your turn
The first two bytes at 900H are 0A then 19. On a little-endian machine, what is the 16-bit instruction word?
Show solution
Little-endian stores the low byte first. The byte at 900H (0A) is the low byte; the byte at 901H (19) is the high byte. The word is 190AH.
Your turn
A program starts at 900H and its last instruction starts at 906H. Each instruction is 2 bytes. What is the program size?
Show solution
Instructions start at 900H, 902H, 904H, 906H—four instructions. Four × 2 bytes = 8 bytes = 64 bits. The last instruction occupies 906H and 907H, so the program ends at 907H.
