Chapter 3

Central Processing Unit

What the CPU must do, the registers it needs, the states an instruction passes through, how interrupts hijack the flow—and how the Z80 makes it concrete.

1CPU organization

The CPU is connected to the rest of the system through the system bus. Internally it has four blocks—registers, ALU, control unit, and internal bus—but the important question is what the CPU has to accomplish:

1 · Fetch instruction

Read the next instruction from memory using the PC.

2 · Interpret instruction

Decode the opcode and operand fields to determine the required action.

3 · Fetch data

Read operands from memory or an I/O module when the instruction needs them.

4 · Process data

Perform the arithmetic or logical operation in the ALU.

5 · Write data

Store the result back to a register, memory, or an I/O module.

To do this, the CPU needs a small internal memory: somewhere to keep the current instruction, the address being accessed, the data in transit, and intermediate results. Those are the registers.

2Register organization

Registers are the top of the memory hierarchy: the fastest storage, and the smallest. The number and function of registers vary between processors and are one of the major design decisions.

User-visible registers

These can be referenced by machine-language instructions:

  • General-purpose—usable for any operand; true general-purpose use means any GPR can hold any operand, though real CPUs often restrict some registers for the stack or addressing.
  • Data registers—hold data only; they cannot be used to compute an operand address.
  • Address registers—hold addresses: segment pointers, index registers, stack pointer.
  • Condition codes (flags)—set by hardware as a result of operations, read by conditional branches, and not directly settable by ordinary programs.

How many? Typically 8–32. Fewer registers means more memory references; more registers means longer instruction encodings to name them. How big? At least large enough for a full address or a full word; often two data registers can be combined into one wider register (as with Z80’s H and L forming HL).

Control and status registers

Used by the control unit and privileged software during fetch, decode, and execution. Many are invisible to the programmer; some are visible but not easily modified.

  • PC—address of the instruction to fetch.
  • IR—the instruction most recently fetched.
  • MAR—address of a memory location.
  • MBR—data written to or read from memory.
  • PSW—condition codes plus status information.
Programming model. The set of registers a programmer may use is called the programming model. Two CPUs can have the same instruction set but different programming models only if the visible state differs—which is why the model is part of the architecture, not the organization.

3The PSW and flags

FieldMeaning
SignSign bit of the last arithmetic result (1 = negative).
ZeroSet when the result is exactly 0.

Flags are outputs, not inputs. An instruction sets them; a later conditional branch reads them. Writing a program that assumes flags survive an unrelated instruction is a classic bug—many instructions modify them.

4Programming models: 8086, 68000, Z80

Intel 8086

16-bit processor, 20-bit address bus, 16-bit data bus.

  • 4 × 16-bit data registers: AX, BX, CX, DX (byte-addressable halves)
  • 4 × 16-bit pointer/index: SP, BP, SI, DI
  • 4 × 16-bit segment: CS, DS, SS, ES
  • Instruction pointer
  • 16-bit flags register, 9 active flags

Physical address = CS × 16 + IP.

Motorola 68000

32-bit registers, 24-bit address bus.

  • 8 × 32-bit data registers D0–D7
  • 8 × 32-bit address registers A0–A7 (A7 is the stack pointer; a second A7 for supervisor mode)
  • 32-bit program counter
  • 16-bit status register

Zilog Z80

8-bit processor, 8-bit data bus, 16-bit address bus.

  • 6 × 8-bit GPR: B, C, D, E, H, L
  • 8-bit accumulator A
  • 8-bit flag register F (6 flags)
  • 4 × 16-bit address registers: IX, IY, SP, PC
  • Special: I (interrupt vector), R (refresh)

The Z80 is the one the controls use, so its details matter most. Pairs:
BC = B·256 + C, DE = D·256 + E, HL = H·256 + L.

Z80 example:
LD A, 20H     ; A = 20H
LD B, 3AH     ; B = 3AH
ADD A, B      ; A = A + B = 5AH

The x86 equivalent is MOV EAX,20H / MOV EBX,3AH / ADD EAX,EBX.

5The instruction cycle

The basic direct instruction cycle contains seven states:

StateMeaningWhat happens
IACInstruction Address CalculationDetermine the address of the next instruction (usually PC, or PC + offset)
IFInstruction FetchRead the instruction from memory into IR
IODInstruction Operation DecodingDecode opcode and operand specifiers
OACOperand Address CalculationCompute the effective address of the operand
OFOperand FetchRead the operand from memory or an I/O module
DOData OperationPerform the operation in the ALU
OSOperand StoreWrite the result back

Not every instruction visits every state, and some states can be visited more than once. The slides give three canonical examples:

InstructionStatesWhy
LOAD A, 30HIAC, IF, IOD, OAC, OFNeeds the operand address, then reads memory; no data operation or store
ADD A, 30HIAC, IF, IOD, DOOperand is implicit (accumulator + immediate); just operate
JUMP 200HIAC, IF, IODOnly changes the PC; no operand fetch or store

In an indirect cycle the operand is itself an address: the fetch returns the address, so an additional memory access is needed to get the actual data. That is why the indirect cycle has multiple OF states.

Book corner — data flow (Stallings §14.3). The fetch cycle has four register transfers: MAR ← PC, MBR ← memory[MAR], IR ← MBR, PC ← PC + I. The indirect cycle adds: MAR ← IR(address), MBR ← memory[MAR], then update the address field of IR. The execute cycle is whatever the opcode requires. The interrupt cycle adds a save of PC and a load of the ISR address. Once you see the cycle as a sequence of register transfers, the exam’s “give the registers after fetch/execute” questions become mechanical.

6Interrupts

An interrupt is a process by which another module (typically I/O) interrupts the normal sequence of processing. It is asynchronous: it can arrive between any two instructions. The alternative, polling, keeps the CPU in a loop checking the device—wasteful when the device is usually idle.

Classes

  • Program—overflow, division by zero.
  • Timer—generated by an internal processor timer for periodic work.
  • I/O—from an I/O device.
  • Hardware failure—memory parity error, bus error.

Types

PairMeaning
Hardware / softwareGenerated by a hardware signal vs. by an instruction (e.g. a trap or system call).
Maskable / non-maskableCan be enabled/disabled or delayed vs. always accepted. NMI is used for catastrophic events.
Vectored / non-vectoredThe ISR address is fixed by hardware vs. supplied by the peripheral or calculated.

The interrupt cycle

The CPU checks for interrupts at the end of the current instruction—never in the middle. If an interrupt is pending and enabled:

  1. Suspend the current program.
  2. Save the context—at minimum the PC (the return address), usually also flags and registers.
  3. Set the PC to the start address of the ISR (Interrupt Service Routine).
  4. Execute the ISR.
  5. Restore the context and continue the interrupted program.

The user program contains no special code for this. The CPU and operating system are responsible for suspending and resuming it.

7Multiple interrupts and priorities

Two approaches handle simultaneous interrupts:

Disable interrupts

While one interrupt is being processed, further interrupts are ignored. They remain pending and are handled in sequence after the current one finishes.

Advantage: simple. Drawback: ignores relative priority and time-critical needs.

Define priorities

A lower-priority interrupt can itself be interrupted by a higher-priority one. When the higher-priority ISR finishes, the CPU returns to the lower-priority one.

This produces nested interrupts and requires a stack of contexts.

The slide’s example

Three devices with priorities: printer = 2, disk = 4, communications = 5 (higher number = higher priority). Each ISR takes 10 time units.

  • t = 0: user program begins.
  • t = 10: printer interrupt (priority 2). ISR would run until t = 20.
  • t = 15: communications interrupt (priority 5) arrives. It is higher than the printer, so it preempts.
  • t = 20: disk interrupt (priority 4) arrives. It is lower than communications (5) but higher than printer (2).

Result: printer starts at 10, is preempted at 15 by communications; disk waits or preempts printer depending on the exact priority rules; each resumed routine continues from where it stopped.

8Z80 in detail

The Z80 is an 8-bit processor with an 8-bit data bus and a 16-bit address bus. It has 158 instructions, 1 to 4 bytes long, and 256 input and 256 output ports.

Register set

8-bit: A (accumulator), F (flags), B, C, D, E, H, L. 16-bit: PC, SP, IX, IY. Pairs: BC, DE, HL. Special: I (interrupt vector), R (refresh).

Machine cycles and T-states

A Z80 instruction cycle is made of one to six machine cycles. Each machine cycle contains three to six T-states (clock cycles):

Machine cycleT-states
1-byte opcode fetch4
1-byte operand fetch3
1-byte memory read3
1-byte memory write3
1-byte I/O read4
1-byte I/O write4

A 16-bit operand fetch is two 1-byte operand fetches; a 16-bit memory read is two 1-byte memory reads.

Worked fetch/execute trace

Take the program from the 2025–26 control, stored at 2000H:

2000H: DD 21 00 30   →  LD IX, 3000H
2004H: DD 7E 00      →  LD A, (IX+0)
2007H: 3C            →  INC A
2008H: DD 77 00      →  LD (IX+0), A
200BH: 76            →  HALT

Fetching LD IX,3000H:

MAR ← PC = 2000H
MBR ← [2000H] = DDH        (first opcode byte)
IR  ← DD
PC  ← 2001H
MAR ← 2001H
MBR ← [2001H] = 21H        (second opcode byte)
IR  ← DD21H
PC  ← 2002H
... then the two operand bytes 00H, 30H are fetched
PC  ← 2004H
IX  ← 3000H

Which byte ends up in MBR at the end of the fetch depends on the definition used: the last byte read. For a 4-byte instruction, that is the high operand byte. Check the control’s convention carefully.

Z80 interrupts

SignalModeISR location
Reset—0000H

INT (maskable)0One of 00H, 08H, 10H, … 38H, selected by external hardware
INT10038H
INT2[(I × 256) + device_data]

It also has eight software interrupts, RST 0 to RST 7. The Z80 saves the context and PC on the stack, fetches the first ISR instruction, and restores the PC at the end.

IM2 address calculation

The I register supplies the high byte, and the interrupting device supplies the low byte. That 16-bit value is a pointer to the ISR address. So there are two memory accesses:

  1. Form the pointer (I × 256) + data.
  2. Read the two bytes at that pointer—that pair is the ISR start address.
I = 23H, device data = 4CH
pointer = 2300H + 4CH = 234CH
ISR address = [234DH][234CH]   (little-endian)
Exam link. 2024–25 Q1.11–1.13 ask for SP and PC before/after the interrupt and for IR, MAR, MBR before fetching the ISR. The sequence is: finish the current instruction → push PC → SP = SP − 2 → PC = pointer → fetch from the ISR address.

9ARM and x86

ARM

  • Load/store model: operations act on registers, not directly on memory.
  • 32-bit register file, with a barrel shifter before the ALU.
  • Conditional execution of most instructions reduces branches.
  • 37 × 32-bit registers total: R0–R12, R13 = SP, R14 = LR (link register), R15 = PC.
  • Multiply/accumulate unit; 6 mode-specific CPSRs and 6 SPSRs.

x86 / Pentium 4

  • 8 × 32-bit general-purpose registers.
  • 6 × 16-bit segment registers.
  • 32-bit flags register and instruction pointer.
  • 8 × 80-bit floating-point registers.
  • 80486 instruction cycle: fetch, decode 1, decode 2, execute, writeback.
  • Interrupts: maskable/non-maskable, exceptions, vector table of 256 × 32-bit entries, 5 priority classes.
The common thread. Every processor has the same conceptual pieces—PC, IR, MAR/MBR, flags, GPRs, an ALU, and a control unit. What changes is the width, the number of registers, the instruction encoding, and the interrupt mechanism. Learn the concept once and the exam’s unfamiliar CPU becomes readable.

Check yourself
How many bytes does LD IX,3000H occupy?
Show reasoning
DD 21 is a two-byte opcode; the 16-bit operand 3000H adds two more bytes. Total 4 bytes: DD 21 00 30 in little-endian order.
Check yourself
Which states are used by INC (HL)?
Show reasoning
The operand is in memory at [HL]: compute its address (OAC), read it (OF), increment it (DO), and write it back (OS). All seven states are used.
Check yourself
Z80 interrupt mode 2, I = 23H, device data = 4CH. Where is the ISR start address stored?
Show reasoning
The pointer is I×256 + data = 2300H + 4CH = 234CH. The two bytes at 234CH and 234DH form the 16-bit ISR address (little-endian). Mode 1 would be fixed at 0038H.
